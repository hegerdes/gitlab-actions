# Pandoc

GitLab CI component that converts documentation with pandoc. The exported files are stored as a job artifact.

Each source file in `docs_dir` (non-recursive) becomes one file in `output_dir`. The file name is used as document title.

## Supported formats

Both formats are case-insensitive (`Markdown`, `PDF` and `markdown`, `pdf` are equal).

| `input_format`       | Source files |
| -------------------- | ------------ |
| `markdown` (default) | `*.md`       |

| `output_format` | Output files |
| --------------- | ------------ |
| `pdf` (default) | `*.pdf`      |
| `word`          | `*.docx`     |
| `html`          | `*.html`     |

## Usage

```yaml
stages:
  - build

include:
  - component: $CI_SERVER_HOST/hegerdes/gitlab-actions/pandoc@<VERSION>
```

Pin `<VERSION>` to a released tag.

Without `extra_args`, pandoc uses its defaults (e.g. `pdflatex` as PDF engine). Engine, layout, fonts, highlighting, headers and additional metadata are all set via `extra_args`. Quoting and command substitution (`$(...)`) work inside `extra_args`.

`extra_args` are format-specific: LaTeX options such as `--pdf-engine`, `-V geometry:...` or `-H file.tex` only make sense for `pdf`. For `word` use e.g. `--reference-doc=template.docx`, for `html` e.g. `--embed-resources` or `--css=style.css`.

### Example: Cloud-Documentation as PDF

```yaml
include:
  - component: $CI_SERVER_HOST/ares-internal/shared/software/code-templates/doc-converter@<VERSION>
    inputs:
      as_job: DOCS:pdf-export
      author: Cloud-Team
      subject: Dokumentation Private-Cloud
      extra_args: >-
        --pdf-engine=lualatex
        --syntax-highlighting=idiomatic
        -H templates/code-listing.tex
        -V geometry:margin=1in
        -V monofont="DejaVu Sans Mono"
        --metadata keywords="docs, cloud, autogenerated, $(date +%F)"
```

`--syntax-highlighting` requires pandoc >= 3.8.

### Example: multiple formats

Include the component once per format with a distinct job name and output directory:

```yaml
include:
  - component: $CI_SERVER_HOST/ares-internal/shared/software/code-templates/doc-converter@<VERSION>
  - component: $CI_SERVER_HOST/ares-internal/shared/software/code-templates/doc-converter@<VERSION>
    inputs:
      as_job: DOCS:word-export
      output_format: word
      output_dir: docx
  - component: $CI_SERVER_HOST/ares-internal/shared/software/code-templates/doc-converter@<VERSION>
    inputs:
      as_job: DOCS:html-export
      output_format: html
      output_dir: html
      extra_args: --embed-resources
```

### Overriding via variables

All inputs except `rules`, `stage`, `image` and `allow_failure` are mapped to job variables, so they can also be changed by extending the job. Runner tags and pull policy can be overridden the same way:

```yaml
DOCS:convert:
  tags: [my-runner]
  variables:
    DOCS_DIR: $CI_PROJECT_DIR/docs
    OUTPUT_FORMAT: html
    PANDOC_EXTRA_ARGS: --toc --number-sections
```

## Inputs

| Input           | Default                          | Description                                                 |
| --------------- | -------------------------------- | ----------------------------------------------------------- |
| `allow_failure` | `false`                          | Continue the pipeline if the job fails.                     |
| `as_job`        | `DOCS:convert`                   | Name of the job.                                            |
| `stage`         | `build`                          | Stage of the job.                                           |
| `image`         | `pandoc/extra:latest-debian`     | Image providing pandoc and LaTeX.                           |
| `input_format`  | `markdown`                       | Source format, see [Supported formats](#supported-formats). |
| `output_format` | `pdf`                            | Export format, see [Supported formats](#supported-formats). |
| `docs_dir`      | `$CI_PROJECT_DIR`                | Directory with the source files.                            |
| `output_dir`    | `pdfs`                           | Output directory, exported as artifact.                     |
| `author`        | `$CI_COMMIT_AUTHOR`              | Document author metadata.                                   |
| `subject`       | `Documentation $CI_PROJECT_NAME` | Document subject metadata.                                  |
| `extra_args`    | `""`                             | Additional pandoc arguments.                                |
| `rules`         | default branch only              | Job rules.                                                  |

## Fixed job settings

| Setting         | Value          |
| --------------- | -------------- |
| Artifact name   | `$CI_JOB_NAME` |
| Artifact expiry | `2 weeks`      |

## Debugging

Set `DEBUG_CI=true` to keep a failed job alive for one hour (e.g. for an interactive web terminal).
